# To-Do List App Implementation Plan

> **For agentic workers:** Implement each task in order. The user requested coding without running the app; do not start the server or execute tests.

**Goal:** Build a responsive Flask to-do app that persists tasks in SQLite and supports add, edit, delete, completion, and status filters.

**Architecture:** Flask serves the page and a JSON task API. A small `todo` package owns app creation, SQLite operations, and routes; browser code in `static/app.js` calls the API and re-renders tasks.

**Tech Stack:** Python, Flask, Python `sqlite3`, HTML, CSS, vanilla JavaScript.

**Spec:** `docs/superpowers/specs/2026-11-07-todo-list-design.md`

## Global Constraints

- Keep the app single-user and local; do not add authentication or external services.
- Persist tasks in a local SQLite database and exclude the database from version control.
- Provide setup and run instructions in `README.md`.
- Do not run the app or tests, per user request. Do not add tests unless requested.

## Review Focus

- Empty or whitespace-only titles must be rejected by the API without changing stored data.
- Unknown task IDs must return a JSON 404 response.
- Invalid filter names must return a JSON client error rather than silently changing the filter.
- A failed browser request must show useful feedback and leave the interface usable.
- Task titles containing HTML characters must render as text, not executable markup.

---

## File Structure

- `app.py`: executable Flask entry point.
- `todo/__init__.py`: app factory, configuration, database initialization, blueprint registration.
- `todo/db.py`: connection lifecycle, schema creation, parameterized task CRUD operations.
- `todo/routes.py`: page route and JSON API validation/response handling.
- `templates/index.html`: semantic page structure and accessible controls.
- `static/styles.css`: responsive styling and focus/complete states.
- `static/app.js`: fetch calls, form handling, filter state, safe task rendering, and request feedback.
- `requirements.txt`: Flask dependency.
- `.gitignore`: Python artifacts, virtual environment, and local SQLite database.
- `README.md`: virtual environment, install, and run instructions.

### Task 1: SQLite persistence and Flask API

**Files:** Create `app.py`, `todo/__init__.py`, `todo/db.py`, `todo/routes.py`, `requirements.txt`, and `.gitignore`.

**Interfaces:**

- `create_app(test_config: dict | None = None) -> Flask` builds the app, initializes the schema, and registers routes.
- `get_db() -> sqlite3.Connection` returns a request-scoped connection.
- Database helpers `list_tasks(filter_name: str) -> list[dict]`, `create_task(title: str) -> dict`, `update_task(task_id: int, fields: dict) -> dict | None`, and `delete_task(task_id: int) -> bool` own parameterized SQL.
- Routes expose `GET /`, `GET /api/tasks?filter=all|active|completed`, `POST /api/tasks`, `PATCH /api/tasks/<id>`, and `DELETE /api/tasks/<id>`.

- [ ] Implement schema initialization for `id`, `title`, `completed`, `created_at`, and `updated_at`, and use a local ignored database path.
- [ ] Implement database helpers with validated filter handling, non-empty trimmed titles, completion updates, and `updated_at` refreshes.
- [ ] Implement the app factory and routes, returning JSON errors for invalid input and unknown IDs; serve `templates/index.html` at `/`.
- [ ] Add Flask as the runtime dependency and ignore local database and Python environment artifacts.

### Task 2: Responsive browser interface

- JavaScript uses the Task 1 API and reloads the current filter after successful mutations.
